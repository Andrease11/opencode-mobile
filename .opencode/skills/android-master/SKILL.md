# Android Master

Use this as the router for work in `android/`. Read `android/AGENTS.md`, the files
being changed, and one comparable implementation before editing.

## Route To The Smallest Skill Set

- Load `android-compose-mvi` for Compose screens, state ownership, effects,
  route/screen boundaries, the `Oc*` design system, insets, or IME.
- Load `android-navigation` for the connect/main graph, type-safe routes, route
  arguments, back handling, or list-detail layouts.
- Load `android-auth-session` for pairing, server passwords, saved servers,
  credential storage, 401 handling, or active-server switching.
- Load `android-opencode-api` for the generated client in `core/api`, the Ktor
  client, SSE events, mapping to domain models, or regenerating the API.
- Load `android-data-boundaries` for repository contracts, local stores,
  domain mapping, transcript reconciliation, or typed data errors.
- Load `android-coroutines` for scopes, suspend APIs, Flow, the shared event
  stream, cancellation, dispatchers, or reconnection.
- Load `android-koin` for dependency registration and runtime parameters.
- Load `android-gradle` for modules, dependencies, the version catalog,
  SDK/AGP configuration, or build types.
- Load `android-testing` for non-trivial logic changes, regression fixes,
  fixtures, fakes, dispatcher control, or test infrastructure.
- Load `android-localization-accessibility` for user-visible copy (English and
  Italian), semantics, TalkBack, focus, RTL, font scale, or adaptive layout.
- Load `android-security` for manifests, cleartext policy, camera permission,
  credential storage, clipboard, or sensitive logging.
- Load `android-performance` only for an evidenced startup, streaming jank,
  recomposition, APK size, R8, memory, or trace problem.
- Load `maestro` only for `.maestro/` test flows.
- Load `android-runtime-verification` after Android behavior/UI changes and for
  install, emulator, ADB, Logcat, crash, or runtime-debug work.

Do not load adjacent skills speculatively. A chat screen change may need
`android-compose-mvi` and `android-data-boundaries`; a color change does not.

## Cross-Skill Boundaries

- Credential storage changes use `android-auth-session` plus `android-security`;
  HTTP client or interceptor changes also use `android-opencode-api`.
- Live event handling uses `android-opencode-api` (decoding),
  `android-data-boundaries` (transcript reduction) and `android-coroutines`
  (stream ownership).
- Koin owns binding and lifetime; Gradle owns which module compiles it.
- Performance work requires evidence. Compose does not optimize speculatively.

## Project Invariants

- Dependency direction is `app -> feature -> core`. Features depend on
  `core:domain`, `core:ui`, `core:mvi` and the repository interfaces; they never
  depend on `:app`, `core:network` or `core:api`.
- `core:api` is generated by `tools/api-gen` (`bun run generate`). Never edit it and never
  hand-write DTOs for OpenCode payloads.
- Generated API models stay inside `core:network`/`core:data`; the UI consumes
  domain models from `core:domain`.
- Screen composables receive immutable state and callbacks. Thin route
  composables resolve ViewModels, collect state/effects and bridge navigation.
- ViewModels extend `BaseViewModel<State, Event, Effect>` from `core:mvi`.
- Use `Oc*` components and `OcTheme`/`MaterialTheme` tokens from `core:ui`.
- Every interactive control has a stable `testTag`.

## Modern But Boring

Prefer the simplest modern solution that fits the existing architecture. Do not
introduce a UseCase, Manager, Coordinator, extra mapper layer, custom Flow
wrapper, custom scope, or Gradle convention plugin unless the problem benefits
from it or an established project pattern requires it.

Do not perform opportunistic migrations: no Navigation 3, Koin annotations,
Ktor, a new DI framework, or a new storage framework during unrelated work. Room
(with KSP) is used only for the transcript and session-list caches in `core/data/cache`; settings and
credentials keep their existing stores.

## Completion

Run module-qualified checks from `android/`, then `./gradlew spotlessCheck
testDebugUnitTest :app:lintDebug :app:assembleDebug` for broad changes. Load `android-runtime-verification`
when runtime behavior can change. Report checks run, device used, and anything
that could not be verified.
