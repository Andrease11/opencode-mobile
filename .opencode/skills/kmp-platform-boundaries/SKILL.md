# KMP Platform Boundaries

Shared code is the default. Platform code exists only where an API is genuinely
platform-specific, and it stays small, named and replaceable.

## Where Code Goes

| Code | Location |
|---|---|
| Domain, ViewModels, mapping, UI, resources | `src/commonMain` of the owning module |
| Android-only APIs (Context, Activity results, CameraX, SpeechRecognizer, Keystore) | `src/androidMain` of the same module |
| iOS-only APIs (UIKit, AVFoundation, Speech, Keychain, Network, posix) | `src/iosMain` of the same module |
| App entry, notifications service, manifest | `:app` (Android only) |
| Navigation, app shell, ViewModel bindings, iOS entry | `:shared` (`MainViewController()` in `iosMain`) |
| Xcode project, Info.plist, Swift host | `iosApp/` |

- `commonMain` never imports `java.*`, `android.*`, `androidx.activity`,
  `androidx.core`, OkHttp, or Okio. CI compiles iOS klibs on Linux and fails on
  leaks: `./gradlew compileKotlinIosSimulatorArm64`.
- Platform files use the `.android.kt` / `.ios.kt` suffix and the same package as
  the `expect` declaration.

## Choosing The Mechanism

- **Interface + Koin binding** for services with state, lifecycle, permissions or
  test fakes: `ServerStore`, `NetworkMonitor`, `AppVisibility`, `ServerDiscovery`
  are interfaces in `commonMain`, bound in `platformDataModule`
  (`core/data/src/{android,ios}Main/.../di/PlatformDataModule.kt`).
- **`expect fun` / `expect val`** for small stateless helpers: number/date
  formatting, logging, IDN conversion, `notificationsSupported`.
- **`expect` composables** for UI that needs a platform view or launcher: QR camera
  preview, attachment picker, dictation, back handling. Keep the shared screen
  and its state in common code; the `actual` only adapts the platform API.
- Avoid `expect class`; when a stateful platform object is needed, prefer an
  interface with platform implementations. Existing `expect object
  CacheDatabaseConstructor` is generated by Room and is the exception.
- Do not fake a platform feature: hide it (`notificationsSupported = false` on iOS)
  and document the gap.

## Common Replacements

| Instead of | Use in commonMain |
|---|---|
| `System.currentTimeMillis()` | `kotlin.time.Clock.System.now().toEpochMilliseconds()` |
| `java.time.*` | `kotlinx-datetime` (`TimeZone`, `LocalDate`); localized text via `expect` |
| `UUID.randomUUID()` | `kotlin.uuid.Uuid.random()` (opt-in) |
| `ConcurrentHashMap`, `synchronized` | `ConcurrentMap` in core:data, atomicfu `SynchronizedObject`, `Mutex` in suspend code |
| `android.util.Base64` | `kotlin.io.encoding.Base64` (padding optional when decoding untrusted data) |
| `String.format` | explicit formatting helpers (`formatDecimal`, `formatInteger`) |
| `BuildConfig` in libraries | values passed from the app (`AppInfo`), `Platform.isDebugBinary` on iOS |
| `@Volatile`, `@JvmInline` | `kotlin.concurrent.Volatile`, `kotlin.jvm.JvmInline` (explicit import) |

## Rules

- Keep Android behavior identical when moving code: the same storage files and
  keys, the same Room database, the same resources and semantics. A migration
  must not change what an upgrading user sees.
- Engines and platform callbacks may run on other threads or coroutines: emit
  from them with `channelFlow { send() }` or `callbackFlow`, never `flow { emit() }`.
- Objective-C exceptions abort the process and cannot be caught in Kotlin; check
  preconditions before calling APIs that raise them (e.g. an empty audio input
  format before `installTapOnBus`).
- New platform features need both actuals or an explicit, documented iOS gap.

## Verification

- `./gradlew :<module>:compileAndroidMain :<module>:compileKotlinIosSimulatorArm64`.
- Runtime changes: `android-runtime-verification` for Android and `kmp-ios` for iOS.
